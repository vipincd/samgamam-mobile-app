## Defects found and fixed

| # | Defect | Evidence | Fix |
|---|---|---|---|
| D1 | **Session refresh always failed.** On a 401, the token-refresh path called `establishAuth0Session` while the expired backend token was still stored; `request()` then overwrote the explicit `Authorization: Bearer <Auth0 token>` header with the expired backend token. `/v1/auth/session` rejected it, so every backend-session expiry signed the user out even with a valid Auth0 refresh token. Affects iOS and Android. | New test `session.test.ts` #7 failed before the fix (`ApiError: Token expired`), passes after. The existing test #5 mocked `establishAuth0Session` and could not catch it. | `src/api/client.ts`: only attach the stored token when the caller has not supplied `Authorization`. |
| D2 | **Deep-link IDs and hosts were not validated.** `samgamam://event/..` produced event ID `..`, which `encodeURIComponent` leaves unchanged, so the app requested `/api/v1/events/..` (normalized to `/api/v1/`). Any `https://` host in a notification `url` was treated as a Samgamam link. | Unit tests; simulator: valid link opens details (GET `/api/v1/events/qa-event`), `samgamam://event/..` and `%2E%2E%2Fme` make **no** request and stay on Discover. | `src/services/deep-links.ts`: IDs must match `^[A-Za-z0-9][A-Za-z0-9_-]{0,127}$`; web links only from `samgamam.com` / `www.samgamam.com`. |
| D3 | **Unused Face ID purpose string.** `expo-secure-store` injected the generic `NSFaceIDUsageDescription` although the app uses no biometrics (`requireAuthentication` unused). | Generated `Info.plist` before and after; built app no longer contains the key. | `app.json`: `["expo-secure-store", { "faceIDPermission": false }]`. Android backup rules unchanged. |
| D4 | **Tab bar broke at large Dynamic Type.** At `accessibility-extra-extra-extra-large`, labels wrapped mid-word ("Disco/ver", "Profil/e"). | Simulator screenshots of the same Release build flow before and after: labels now fit on one line at AX5. | `App.tsx`: tab labels `maxFontSizeMultiplier={1.3}`, `numberOfLines={1}` (native iOS tab bars do not scale labels with Dynamic Type either). |

## Native configuration and security review

- **ATS:** `NSAllowsArbitraryLoads=false`, `NSAllowsLocalNetworking=true` (Expo default; still in Release). Low risk; recommend removing it for production builds.
- **URL schemes:** `samgamam`, `com.samgamam.mobile` (Auth0 callback), `exp+mobile-app` (from `expo-dev-client`, also present in Release). No Associated Domains, so `https://samgamam.com` links do not open the app on iOS (universal links not implemented).
- **Entitlements:** only `aps-environment = development`. Not changed. Production push requires the production environment through distribution signing; not enabled here.
- **Privacy manifest:** required-reason API declarations come from the SDKs; `NSPrivacyTracking=false`; `NSPrivacyCollectedDataTypes` is **empty** although the app handles email, name, user ID, device ID/push token and user content. Product/legal must decide the declarations; not changed here.
- **Purpose strings:** Camera (QR check-in) only, after D3. No microphone, location, photos or tracking.
- **Logging:** no `console.*` calls in app source; error messages are sanitized (`getSanitizedAuthMessage`).
- **Logout:** revokes the backend token (`/v1/auth/revoke`), clears the Auth0 session and `CredentialsManager`, and deletes the stored token (session test #4). The push registration is removed through `DELETE /v1/devices/register`.
- **Release configuration:** production builds fail closed to HTTPS on `samgamam.com`/`api.samgamam.com` and disable the API URL override (`app.config.test.ts`).

**Coordination needed:** the iOS and Android acceptance runs cannot run at the same time on one machine,
because both builds are fail-closed to `http://127.0.0.1:4318`. Serialize them, or give each platform's
acceptance build its own mock port, and avoid `kill -9` on the port in shared scripts.

## Release-readiness blockers (not fixed here)

1. **In-app account deletion is missing.** The app creates accounts through Auth0 sign-in, and the backend
   has `POST /api/auth/delete-account`, but the mobile app has no deletion entry point. App Review requires
   one for apps with account creation (verify against the current App Review Guidelines). Shared feature;
   coordinate with Developer C and Developer A.
2. **Sign in with Apple:** if the Auth0 Universal Login offers third-party social providers, the current
   guidelines may require an equivalent privacy-preserving option. Depends on tenant configuration; verify.
3. Privacy manifest collected-data declarations and the App Store privacy label (see above).
4. Universal links (Associated Domains + `apple-app-site-association`) are not implemented.
5. Distribution signing, production `aps-environment`, a TestFlight build and real-device runs need an Apple team and separate authorization.
6. Crash reporting is not integrated.
7. VoiceOver, Reduced Motion, camera permission denial, physical performance and real Auth0/push flows still need physical-device verification.
