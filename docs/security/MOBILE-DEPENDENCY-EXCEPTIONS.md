# Mobile Dependency Security Exceptions

**Date:** 2026-10-02  
**Branch:** `feature/samgamam-world-class-production-readiness`  
**Review deadline:** 2026-11-15

## Policy

Mobile CI fails on any high- or critical-severity npm advisory unless the advisory is explicitly listed in `scripts/security-audit.cjs` and the exception has not expired.

Exceptions are advisory-specific, package-specific, and time-bounded. A new advisory ID, a critical advisory, a different affected package, or an expired exception fails CI.

| Advisory | Package | Severity | Reason for temporary exception |
| --- | --- | --- | --- |
| `GHSA-5p2g-fcmc-qvqq` | `image-size` | High | Metro reaches the package during asset processing. No patched npm release is available as of 2026-10-02. |
| `GHSA-w3rx-r6r6-pgpr` | `image-size` | High | Same Metro dependency. The advisory references a 2.0.3 patched version, but no such npm release is available as of 2026-10-02. |
| `GHSA-86w9-cpqp-85rv` | `node-forge` | High | Expo CLI / code-signing certificate tooling reaches node-forge 1.4.0. No fixed release is published yet; upstream fixes are still under review. Samgamam application code does not import this tooling or expo-updates signing APIs. |

The `image-size` findings are reached through Metro's asset-dimension build path. Samgamam does not use `image-size` as a runtime server endpoint for arbitrary uploaded images.

The `node-forge` finding is reached through Expo CLI and `@expo/code-signing-certificates`. Source review confirms those helpers can invoke RSA signature verification, so this exception is not based on claiming the vulnerable code does not exist. The acceptance is narrower: Samgamam imports none of the certificate helper APIs, `expo-updates`, or `node-forge` in application code, and the affected tooling processes trusted repository/build configuration in the current release workflow.

The lockfile was regenerated by npm rather than edited manually.

## Remaining moderate advisory

`uuid` is currently reached through the Xcode project tooling dependency. The compatible dependency chain still selects `uuid@7.0.3`; npm's suggested forced remediation would replace the tested Expo stack with an incompatible older version. This moderate advisory does not pass the high-severity release threshold silently: it remains visible in the audit output and must be re-evaluated during the next Expo/toolchain upgrade.

## Removal criteria

Remove an exception immediately when any of the following becomes true:

1. a compatible patched `image-size` or `node-forge` release is published and supported by Expo/Metro,
2. Expo/Metro stops depending on an affected package/version,
3. a currently excepted build path becomes reachable from attacker-controlled input in Samgamam,
4. Samgamam begins importing Expo code-signing helpers or update-signing APIs directly,
5. the review deadline is reached.

No exception in this file authorizes ignoring a critical advisory.
